# MINI REDIS

## 개요
C++20으로 구현한 학습용 HTTP 키-값 저장소입니다. 문자열 저장·조회, TTL, 영구 카운터를 제공하며 AOF로 데이터를 복구합니다. 다중 요청 환경에서 조회 지연, 키 만료 처리, 장애 복구와 쓰기 보장 범위를 직접 다뤄보며 저장소 내부 동작을 정리했습니다.

## 설계 목표
메모리 기반 저장소는 조회가 빠르지만, 단일 실행 흐름에서 파일 입출력이나 해시 테이블 확장을 한꺼번에 처리하면 다른 조회 요청까지 함께 지연될 수 있습니다.
- **조회 지연 최소화**: AOF 기록이나 리사이즈 중에도 조회가 과도하게 막히지 않도록 구조를 나눕니다.
- **명확한 일관성과 내구성 보장**: 장애 발생 시 복구 가능성과 쓰기 응답이 보장하는 범위를 구분해 다룹니다.

## 특징

### 1. 백그라운드 AOF 기록과 쓰기 응답 보장
- **도입 이유**: 이벤트 루프에서 AOF에 직접 쓰면 디스크 기록이나 `fsync`가 늦어질 때 다른 연결의 `GET` 요청까지 함께 밀립니다. 또한 일반 키-값 쓰기와 재시도가 잦은 카운터는 요구하는 내구성 수준이 다릅니다.
- **적용 방식**:
  - AOF 기록(`append`)과 `fsync`를 별도 스레드로 분리했습니다. 일반 키는 기록이 끝나면 이벤트 루프가 메모리에 반영하고 `204`를 응답하며, 그사이 다른 연결은 마지막으로 반영된 값을 읽습니다.
  - 카운터는 네트워크 응답 유실 등으로 같은 요청이 재전송되더라도 중복 반영되지 않도록 카운터 변경과 이벤트 ID를 한 레코드에 기록하고, `fsync`가 끝난 뒤 응답하도록 처리했습니다. (일반 키의 `204`는 주기적 `fsync` 전까지 전원 장애 시 유실 가능성이 있습니다.)

### 2. 점진적 재해싱(Incremental Rehashing)
- **도입 이유**: 해시 테이블 버킷을 늘릴 때 모든 키를 한 번에 옮기면 이동이 끝날 때까지 이벤트 루프가 다른 요청을 처리하지 못합니다.
- **적용 방식**:
  - 기존 버킷 배열과 새 배열을 함께 두고, 한 단계에 노드를 최대 4개씩 나누어 옮깁니다.
  - 이동 중에는 두 배열에서 모두 키를 조회할 수 있도록 했습니다. 전체 이동 시간은 늘어나더라도 한 번에 조회를 막는 최대 지연 시간을 줄이는 쪽을 선택했습니다.

### 3. TTL 최소 힙(Min-Heap)
- **도입 이유**: 만료 대상 키를 찾기 위해 전체 키를 순회하면, 만료 키가 적더라도 탐색 비용이 전체 키 수에 비례합니다.
- **적용 방식**:
  - TTL이 있는 키만 최소 힙에 넣고, 각 키가 자신의 힙 인덱스를 기억하도록 해 TTL 갱신이나 삭제 시 위치를 바로 조정할 수 있게 했습니다.
  - AOF에는 절대 만료 시각을 남겨 재시작 후에도 남은 TTL을 처음부터 다시 계산하지 않도록 했습니다.
